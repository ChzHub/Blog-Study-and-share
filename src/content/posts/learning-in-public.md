每天都会遇到新的概念、新的工具，也会收藏不少“以后再看”的文章。但接触过，并不等于理解了。**把学习的过程写下来**，是让模糊的印象逐渐变清晰的一种方式。

## 从一个具体的问题开始

与其一开始就试着建立庞大的知识库，不如先记录今天遇到的一个问题。比如：为什么一个异步函数返回的总是 Promise？为什么设置了宽度的元素依然会溢出？

具体的问题会自然地带来检索、验证和解释，也会让一篇笔记有清楚的边界。

### 笔记不是收藏夹

复制一段解释很容易，但更有帮助的做法，是用自己的语言再说一遍。如果无法讲清楚，就把卡住的地方也写下来。

可以从这三个问题开始：

1. 我最初想解决什么问题？
2. 哪个例子改变了我的理解？
3. 下一次遇到类似问题，可以怎样更快定位？

## 给知识建立连接

一篇孤立的笔记，往往只能回答一个问题。把相关笔记连起来，才会慢慢看到结构。数字花园的价值就在这里：内容不必一次完成，可以随着理解不断生长。

例如，关于 CSS Grid 的笔记，可以连接到响应式设计，也可以连接到浏览器如何计算布局。

```ts
type Note = {
  title: string;
  question: string;
  connections: string[];
};

const note: Note = {
  title: '理解异步任务',
  question: 'Promise 回调什么时候执行？',
  connections: ['事件循环', '浏览器渲染'],
};
```

## 为回看留下入口

一篇笔记有没有用，也取决于未来能不能找到它。标题尽量具体，用少量稳定的标签组织内容，并定期回看旧笔记。

| 记录方式 | 适合的内容 |
| --- | --- |
| 问题笔记 | 一个可以复现的技术问题 |
| 主题文章 | 已经整理过的完整理解 |
| 阅读摘记 | 一段值得继续追问的观点 |

## 让积累保持轻盈

不需要每天发布，也不需要把每一次学习都变成正式文章。保留一点空白，让记录成为思考的工具，而不是新的负担。

先写一小段。下一次回来时，你可能会看到昨天没有看到的连接。
