> 示例文章：以下代码是一个只读检查示例，不会修改文件。

自动化不一定需要复杂的平台。有时候，一个几十行的小脚本，就能把容易遗漏的检查变成稳定的步骤。

## 从重复的检查开始

例如，每次发布前，都要确认文章有没有标题和摘要。与其依赖记忆，不如让构建过程主动检查，并在信息不足时停止。

## 先观察，再行动

第一版脚本可以只输出结果。确认规则合理之后，再决定是否加入写入行为。只读检查更容易验证，也方便定位误报。

```js
import { readdir } from 'node:fs/promises';

const files = await readdir('./src/content/posts');
const markdownFiles = files.filter(file => file.endsWith('.md'));

console.log(`找到 ${markdownFiles.length} 篇 Markdown 文章`);
```

### 明确失败时的行为

缺失目录、解析错误或字段不完整，都应该带来清楚的提示。脚本的使用者不应该通过猜测，判断它到底有没有成功。

## 让脚本成为工作流的一部分

把脚本放在项目里，记录运行方式，并接入持续集成。自动化的收益来自持续使用，而不是第一次运行时节省的几分钟。
